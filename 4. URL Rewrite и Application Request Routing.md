## Перенаправление

Продолжим разбирать функционал IIS и сейчас рассмотрим случай, когда нам необходимо перенаправить запрос клиента с HTTP на HTTPS. Для этого идеально подходит механизм `URL Rewrite`. 

Продолжим работать с нашим сайтом. У него есть 2 привязки `http:*:8080` и `https:*:8443`. Наша задача весь трафик с порта 8080 направить на 8443. Для этого необходимо:

1. Открыть `URL Rewrite` для этого сайта.

2. Нажмем `Add Rule(s)`, затем `Inbound Rules` и `Blank rule`. После чего называем правило.

3. Первое, что сделаем это создадим регулярное выражение для совпадения URL-адреса. Выберем "соответствие шаблону" и "регулярное выражение".  В нашем случае мы хотим проверять весь трафик поэтому регулярное выражение будет выглядеть просто как `(.*)`, то есть под это правило попадет любой запрос клиента. 

4. Затем создадим условия. Если мы хотим перехватывать весь HTTP трафик, то будет достаточно одного условия. Ввод условия `{HTTPS}`, указываем чтоб "соответствовал условию" и шаблон `^OFF$`. Таким образом мы проверяем, что `{HTTPS}` равен `OFF` (то есть запрос пришёл по HTTP).

5. Если мы хотим перенаправлять только HTTP с порта 8080, а не весь, то можем добавить еще одно условие. Оно будет выглядеть как, ввод условия `{SERVER_PORT}`, указываем чтоб "соответствовал условию" и шаблон `^8080$`. Здесь мы уже проверяем, что порт сервера соответствует номеру 8080. 

6. Последним шагом будет настроить действие. Так как мы настраивали перенаправление, то и выбираем `Redirect`, адрес перенаправления указываем `https://server:8443/{R:1}`, тип перенаправления указываем `307`. 

 Теперь у нас работает перенаправление с порта 8080 направить на 8443. 

## Проксирование

Также очень полезной функцией будет проксирование. Оно позволяет незаметно для пользователя перенаправить запрос на другой сервер или на внутреннее приложение.

Рассмотрим пример, когда у нас есть приложение расположенное на 3000 порту, но политики межсетевого экрана настроены так, что у пользователей есть доступ только к стандартным портам 80 и 443. В таких ситуациях на помощь приходит проксирование. Мы создаем правило по которому весь трафик с 80 и 443 порта перенаправляется на локальный 3000 порт незаметно для клиента. 

Для реализации данной идеи необходимо установить 2 компонента `URL Rewrite` и `Application Request Routing`. После установки открываем `IIS Manger` и переходим к настройке `Application Request Routing`.

Переходим в `Application Request Routing Cache`, справа в `Actions` выбираем `Server Proxy Settings` и ставим флаг `Enable proxy` и нажимаем `Apply`. Также во избежание проблем в будущем рекомендуется выключить кэширование. Для этого здесь же убираем галочку с `Reverse rewrite host in response headers` и `Enable disk cache`, а в поле `Memory cache duration` пишем `0`.

Теперь нам нужно настроить `URL Rewrite`, для этого следует:

1. В функции `URL Rewrite` нажимаем `Add Rule(s)`, затем `Inbound Rules` и `Blank rule`. После чего назвать правило.

2. Первое, что сделаем это создадим регулярное выражение для совпадения URL-адреса. Выберем "соответствие шаблону" и "регулярное выражение".  В нашем случае мы хотим проверять весь трафик поэтому регулярное выражение будет выглядеть просто как `(.*)`, то есть под это правило попадет любой запрос клиента. 

3. Затем создадим условия. Если мы хотим перехватывать весь HTTP трафик, то будет достаточно одного условия. Ввод условия `{HTTPS}`, указываем чтоб "соответствовал условию" и шаблон `^OFF$`. Таким образом мы проверяем, что `{HTTPS}` равен `OFF` (то есть запрос пришёл по HTTP).

4. Если мы хотим перенаправлять только HTTP с порта 80, а не весь, то можем добавить еще одно условие. Оно будет выглядеть как, ввод условия `{SERVER_PORT}`, указываем чтоб "соответствовал условию" и шаблон `^80$`. Здесь мы уже проверяем, что порт сервера соответствует номеру 80. 

5. Условий у нас не будет и сразу перейдем к настройку действия. Так как мы настраивали проксирование, то и выбираем `Rewrite`, адрес перенаправления указываем `http://localhost:3000/{R:1}`. 

 Теперь у нас работает проксирование всего с порта 80 направить на локальный сокет 3000.
